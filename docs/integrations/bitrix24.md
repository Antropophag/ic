# Интеграция с Bitrix24

Старые заявки читаются из универсального списка Bitrix24 через входящий вебхук
со scope `lists`. Интеграция не вызывает методы изменения Bitrix24.

Секретный базовый URL хранится только в `BITRIX24_WEBHOOK_URL`. Его запрещено
добавлять в Git, логи, PR, задачи и скриншоты. Вебхук должен принадлежать
неадминистративному пользователю с правом чтения исходного списка.

## Безопасная разведка

```bash
docker compose exec backend php yii bitrix/inspect --max-pages=1
```

Команда выводит только количество записей, статусы и число вложений. Названия,
описания, ФИО и ссылки на документы не выводятся. Значение `--max-pages=0`
обрабатывает все страницы, оставаясь в read-only режиме.

`DETAIL_TEXT` списка содержит JSON. Маппер использует разрешённый набор полей и
не переносит телефоны, адреса, даты рождения, соцсети и другие избыточные данные
вложенного профиля Bitrix24.

Реальные записи допустимы только в локальной demo-БД или в контролируемом
миграционном контуре. Тесты CI используют исключительно синтетические данные.

## Импорт в локальную БД

Команда импорта по умолчанию выполняет dry-run и не меняет БД:

```bash
docker compose exec backend php yii bitrix/import --max-pages=1
```

Запись включается только явным параметром:

```bash
docker compose exec backend php yii bitrix/import --max-pages=1 --apply=1
```

Повторный запуск пропускает заявки с тем же `legacy_id`. Для авторов создаются
неактивные технические учётные записи только с идентификатором Bitrix24, именем и
подразделением. Телефоны, адреса, даты рождения, email и социальные профили не
сохраняются. Команда возвращает ненулевой код, если часть исходных записей не
прошла строгую нормализацию, даже когда остальные записи были импортированы.
