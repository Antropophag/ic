# Email-уведомления

Портал уведомляет участников процесса на каждом значимом шаге: регистрация
заявки, назначение исполнителя и эксперта, новый комментарий, публикация
заключения, решение СБ. Список событий и получателей соответствует разделу
«Уведомления» `docs/product-spec.md`.

## Outbox

Письмо ставится в очередь (`notification_outbox`) в той же транзакции, что и
бизнес-событие (NTF-002): содержимое рендерится сразу и запись самодостаточна,
поэтому временная недоступность SMTP не влияет на бизнес-транзакцию (NTF-001).
Фактическую отправку выполняет сервис `scheduler` (`compose.yaml`,
`compose.demo.yaml`) — раз в минуту вызывает:

```bash
php yii notification/send
```

Команда обрабатывает до 50 готовых записей. `next_attempt_at` служит двум
целям: как аренда захвата (`status = sending`) — обработчик, упавший после
захвата записи, освобождает её через 5 минут для повторного захвата другим
запуском, — и как момент следующей попытки после ошибки. Захват атомарен и не
приводит к повторной отправке при параллельном или повторном запуске
(NTF-003). После ошибки задержка растёт экспоненциально (60с, 120с, … до
1 часа); после 5 попыток запись переходит в `failed` и требует ручного
разбора.

## SMTP

Настройки читаются из переменных окружения: `SMTP_HOST`, `SMTP_PORT`,
`SMTP_SECURE`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_VERIFY_PEER`,
`MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME`. Пароль хранится только в локальном
`.env` и не должен попадать в Git, логи, PR или задачи.

Проверка TLS-сертификата включена по умолчанию (`SMTP_VERIFY_PEER=1`).
Внутренний релей использует самоподписанный сертификат, поэтому для него
`.env.example` явно задаёт `SMTP_VERIFY_PEER=0` — это осознанная настройка
конкретного релея, а не поведение кода по умолчанию.

Текущий тестовый ящик `k2mailer@shlz.ru` — временное решение до появления
выделенного адреса для портала.

## Известное ограничение локального контура

Из части сетевых окружений (включая текущий контур разработки) релей
`10.178.69.91:587` принимает TCP-соединение, но сразу закрывает его без
ответа — типичный признак фильтрации по IP на стороне релея. Функциональность
outbox (постановка в очередь, идемпотентный захват с арендой, backoff)
проверена тестами и вручную; фактическая доставка требует проверки с машины,
имеющей доступ к релею (например, целевой demo-машины в корпоративной сети).
