# Статус подготовки миграции Bitrix24 на 2026-08-06

Документ фиксирует результат исследовательского этапа issue #137 и границу
готовности. Реальный импорт в целевую БД не выполнялся; наличие snapshot и
download checkpoint не означает готовность production-миграции.

## Выполнено

- Создан полный неизменяемый snapshot формата 2: 2496 заявок, определения
  полей и 101 минимизированный профиль автора. Manifest содержит количество,
  границы времени, размеры и SHA-256 каждого файла.
- Два последовательных полных среза совпали по `ID`, `CODE`, `NAME`,
  `DETAIL_TEXT` и файловым ID; источник был стабилен во время проверки.
- Подтверждено, что отображаемый номер заявки равен `ID` элемента. Диапазон —
  6502–29912, дубликатов нет; пропуски сохраняются.
- Инвентаризированы фактические статусы. В первую волну входят 2435 выполненных,
  отказанных и отозванных заявок; 61 незавершённая заявка отложена.
- Подтверждены 8534 файловые связи: 5268 сопроводительных документов и 3266
  отчётов, 8484 уникальных исходных файла. Связи вынесены в закрытый
  `associations.jsonl`, бинарники дедуплицируются по исходному файловому ID.
- Реализована возобновляемая браузерная выгрузка файлов с OAuth-профилем,
  allowlist URL, временным файлом, лимитом размера, SHA-256 и checkpoint.
- Выгружены и проверены все 8484 уникальных бинарника: 22 886 524 693 байта,
  failed-записей в актуальном checkpoint и `.partial`-файлов нет. Для
  повреждённых legacy URL загрузчик безопасно перебирает варианты с одним
  потерянным `+`; связи 8534 записей сохранены отдельно от дедуплицированных
  объектов.
- Webhook получил read-only доступ к `user.get`. У всех 101 авторов есть
  уникальные email, корректный AD login (часть email до `@`) и заполненные имя
  и фамилия; 64 профиля активны, 37 неактивны.
- Согласовано изменение первоначальной модели issue: авторы связываются с
  реальными локальными AD identities по вычисленному `ad_login`. Новый активный
  профиль получает роль `employee`, неактивный остаётся заблокированным;
  существующий локальный профиль импорт не перезаписывает.
- Импорт сохраняет исходный `ID` как `requests.number`, а `legacy_id` — как
  отдельный идемпотентный ключ. Номерная последовательность поднимается только
  вверх до максимального фактически импортированного номера.

## Осталось реализовать

- Перевести importer с живого Bitrix24 API на проверенный snapshot формата 2.
- Добавить жёсткий отбор первой волны: запись только терминальных заявок;
  незавершённые должны попадать в отчёт с явной причиной пропуска.
- Сформировать полный dry-run причин невалидности полей и согласовать допустимые
  нормализации до любой записи в БД.
- Реализовать явную архивную модель заявки (`source`/`is_archived` или
  эквивалент), backend read-only ACL для всех мутаций, API-поля, фильтр и
  обозначение архива во frontend.
- Реализовать отдельный идемпотентный импорт документов и версий из
  `associations.jsonl`/`objects`, включая одинаковые имена, общий бинарник у
  нескольких заявок, MIME/размеры, карантин и reconciliation.
- Зафиксировать стратегию диапазона новых номеров. Текущий код поднимает
  sequence до максимального импортированного номера; требование issue о
  `bitrix_number_high_watermark + configurable_number_gap` ещё не реализовано.
- Подтвердить сознательно исключаемые данные: история переходов, назначения,
  комментарии и дата изменения, если источник не даёт согласованного полного
  представления.
- Подготовить production runbook: момент среза и прекращение записи в Bitrix24,
  вторая волна 61 заявки, backup/restore, роли, объём хранилища, ручная выборка
  приёмки, срок хранения артефактов и отзыв webhook/OAuth-профиля.
- Выполнить итоговую сверку по каждой заявке и каждой файловой связи. Только
  после неё issue #137 может считаться завершённым.

## Проверки этого этапа

- `make check`: OpenAPI, frontend lint/audit/tests/build, Composer
  validate/lint/analyse/audit/tests, repository contracts и Markdown lint.
- `make e2e`: чистые миграции, integration suite, Playwright и runtime recovery
  LDAP/SMTP/MariaDB, корректное завершение scheduler.
- Реальные персональные данные, URL файлов, webhook и OAuth credentials не
  коммитятся; snapshot, inventory, checkpoint и бинарники находятся вне Git.
