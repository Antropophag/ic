# Инвентаризация Bitrix24 от 2026-08-06

## Границы проверки

Выполнены два полных read-only снимка универсального списка `114`. Второй
снимок явно выбирал стандартные поля и все определения `PROPERTY_*`. Оба среза
содержат 50 страниц и 2496 элементов; `sourceTotal` совпал с фактическим числом
строк. Контрольные суммы проекции `ID`, `CODE`, `NAME`, `DETAIL_TEXT` двух
снимков совпали, то есть карточки не изменились между чтениями.

Реальные JSONL-файлы и полный per-record отчёт содержат корпоративные данные,
хранятся вне Git в закрытом миграционном каталоге и в этот документ не входят.

## Нумерация

Ручная сверка с интерфейсом подтвердила, что номер заявки равен `ID` элемента.

| Показатель | Значение |
|---|---:|
| Всего номеров | 2496 |
| Уникальных номеров | 2496 |
| Минимальный номер | 6502 |
| Максимальный номер / high-water mark | 29912 |
| Дубли | 0 |
| Пропущенные значения внутри диапазона | 20915 |

Пропуски ожидаемы: `ID` Bitrix24 не является локальной плотной
последовательностью этого списка. Они сохраняются и не заполняются импортом.
Размер configurable gap и ожидаемый первый номер новой заявки определяются до
переключения отдельным эксплуатационным решением.

`NAME` одинаков у всех элементов и не содержит номера. `CODE` уникален, но не
числовой. В `DETAIL_TEXT` отдельного поля номера нет.

## Файлы

| Источник | Записей с полем | Ссылок на файлы | Структура элемента |
|---|---:|---:|---|
| `DETAIL_TEXT.supportingDocFiles` | 2496 | 5268 | `detailURL`, `id`, `name` |
| `DETAIL_TEXT.reportFiles` | 2496 | 3266 | `detailURL`, `id`, `name` |
| `PROPERTY_648` | 0 | 0 | отсутствует в ответах |

`PROPERTY_648` имеет определение «Сопроводительная документация» с файловым
типом, было явно включено в `SELECT`, но Bitrix24 не вернул поле ни для одного
элемента. Фактические источники файлов — два массива внутри `DETAIL_TEXT`.
`PROPERTY_646` — строковое поле «Статус синхро с 1С», не источник документов.

Все 8534 `detailURL` используют HTTPS, один исходный host и каталог
`/docs/file/FilesProposalTest/`; пустых ID, имён и URL нет. Обнаружены 8484
уникальных файловых ID и 32 группы повторных ссылок, из которых 30 встречаются в
разных заявках. URL и имя внутри каждой группы совпадают. Прямой HTTP-запрос без
браузерной сессии переводится на `/oauth/authorize/`, поэтому webhook для
скачивания этих файлов неприменим.

Основные расширения: PDF — 6148, DOCX — 1094, TIF — 478, JPG — 251, ZIP — 248,
7Z — 86. Также присутствуют JPEG, PNG, XLSX, URL, DOC, RAR, MSG, PPTX, TIFF,
BMP, GRB, MP4, TXT и WEBP. Расширение источника не считается доказательством
фактического MIME.

Последующий read-only этап выгрузил все 8484 уникальных объекта общим объёмом
22 886 524 693 байта. Для каждого объекта checkpoint содержит фактический размер
и SHA-256; офлайн-проверка повторно сверяет хеши, полный набор файловых ID и все
8534 связи. Проверка содержимого офисных архивов и допустимости MIME остаётся
частью будущего импорта и карантина, а не доказательством на уровне расширения.

## Качество данных

- некорректных JSON-объектов `DETAIL_TEXT`: 0;
- пустых или повторяющихся `ID`: 0;
- расхождений количества строк с `sourceTotal`: 0;
- изменений карточек между двумя полными снимками: 0.
