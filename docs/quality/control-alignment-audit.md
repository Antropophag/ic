# Аудит вертикального выравнивания контролов

Дата: 25.11.2026. Основа: актуальный `main`, `41b17d4`.

## Область

Проверены шаблоны `App.vue`, всех компонентов `frontend/src/components/`,
общие стили, `admin.css`, подключённые SHLZ-компоненты, development-переключатель,
обзор и встроенная справка. Инвентаризация нашла 138 строк с интерактивными
элементами и индикаторами; повторяющиеся экземпляры сведены к семействам CSS.
Аудит касается вертикального выравнивания, а не полной сертификации доступности.
Архивный `prototype/` и растровые иллюстрации инструкций не являются runtime UI.

## Причины и исправления

1. **P2: фиксированная высота строки в однострочных контролах.** При масштабе
   портала 110% Chromium размещал текст кнопок руководителя на 0,796875 CSS px
   выше центра. `align-items:center` уже присутствовал: смещался текст внутри
   строки. При `line-height:normal` отклонение стало нулевым. Аналогичный дефект
   обнаружен у общих кнопок и SHLZ Button (0,75 px в проверенном варианте).
   Для однострочных контролов используется естественная строка шрифта;
   заданные высоты, размеры шрифта и горизонтальные отступы сохранены.
2. **P2: нативное размещение содержимого компактных кнопок.** Кнопки повторной
   загрузки, сброса фильтров и истории получили явное flex-центрирование;
   закрытие истории/справки — grid-центрирование и нулевые внутренние отступы.
3. **P3: асимметрия индикатора сервиса.** В `.admin-service-head .badge`
   верхний padding был 1 px, нижний — 0. Отступы сделаны симметричными.

Сгенерированные SHLZ-файлы не изменены: адаптация Button находится в прикладном
CSS. Многострочные тексты, textarea, подписи полей, табличные ячейки и ссылки
с собственной высотой строки сохраняют свою типографику. Геометрия стрелок,
checkbox/radio и позиционные transform не являются смещением текста.

При проверке SonarCloud дополнительно объединены повторные CSS-правила без
изменения их значений, повышен контраст счётчика вкладки существующим токеном
`--muted`, движение кнопки шаблона документа ограничено режимом
`prefers-reduced-motion:no-preference`. Цветовая обратная связь сохранена.

## Регрессионные проверки

`frontend/e2e/control-alignment.e2e.js` использует реальную карточку с
синтетическим API-ответом и загруженные production-стили для таблицы вариантов.

- Карточка: ширины 390/1024/1440 px, масштабы 100/110/125%, действия руководителя,
  одинаковые высоты select/button, открытие и закрытие истории, подтверждение
  отказа, disabled-кнопка подтверждения и иконки закрытия.
- 24 варианта кнопок, статусов и счётчиков: измерение границ текстовых узлов
  через DOM Range; допустимое отклонение от центра — 0,5 CSS px.
- 10 вариантов нативных input/select: проверка окрашенных пикселей снимка,
  поскольку внутренний текст недоступен DOM Range. Проверяются наличие текста,
  отсутствие вертикального обрезания и разница верхнего/нижнего просвета не
  более 4 пикселей (смещение центра не более 2 px с учётом рисунка букв).

RED: до исправления тест карточки падал на «Начать работу» при всех трёх
ширинах; тест семейств — на общей кнопке, затем выявил тот же дефект в SHLZ.
GREEN: исправление проверяется теми же геометрическими утверждениями.
Рисунок конкретных букв может быть оптически асимметричен относительно строки;
проверка не требует одинакового положения чернил у слов с разными выносными
элементами. Нативные выпадающие меню ОС не стилизуются приложением.

Команда штатной браузерной проверки (с поднятым test deployment):

```sh
cd frontend
E2E_BASE_URL=http://localhost:18080 npx playwright test control-alignment --project=chromium
```

Визуально проверены desktop/mobile снимки карточки. Механический Impeccable
детектор для изменённых CSS не выдал замечаний. Результаты полного CI и
независимого semantic review фиксируются в PR; откат — revert коммита исправления.
