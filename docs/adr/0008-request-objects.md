# Объекты заявки с общим процессом

Статус: принято для реализации #326, локальная приёмка до публикации.

Заявка содержит 1–10 упорядоченных объектов с наименованием и текстовым
количеством образцов. Производитель, поставщик и объём испытаний принадлежат
заявке; workflow, экспертиза, решения, документы и права остаются общими.
Объекты хранятся в дочерней таблице: это позволяет искать по каждой позиции
без конкатенации строк и сохраняет порядок для документов. JSON в одном поле
отклонён из-за усложнения поиска и контроля целостности.

Старый формат создания с productName/sampleQuantity поддерживается как одна
позиция. Новый формат содержит objects с теми же именами полей; количество
в нём — непустой текст до 15 символов. Одновременное использование форматов
отклоняется. Наименование новой позиции ограничено 500 символами.

Старые scalar-поля ответа сохраняются как совместимое представление первой
позиции. Числовое количество возвращается только если текст является числом;
в остальных случаях null. Оно никогда не означает сумму образцов. Реестр
показывает object_count, карточка получает полный objects. Документы и письма
для нескольких позиций перечисляют все объекты с количеством; старое
однопозиционное оформление сохраняется.

Миграция переносит старые и архивные заявки в одну позицию без обрезки исходных
наименований и количества. Исторические значения могут превышать ограничения
нового ввода. Импорт и development seed сохраняют тот же инвариант. Чтение
старого scalar-представления допустимо для записей без дочерних строк.

Откат миграции проверяет отсутствие нескольких позиций и новых текстовых
количеств, не представимых в старой схеме. Если они появились, откат запрещён
до восстановления резервной копии; данные не обрезаются и не удаляются молча.
Перед обновлением стенда выполняется отдельный backup без сброса volumes.
