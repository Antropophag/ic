# ADR 0005: YAML-first OpenAPI-контракт

## Статус

Принято.

## Контекст

HTTP API Yii2 исторически описан в `docs/api.md` и закреплён integration/E2E
тестами. Контроллеры возвращают массивы, а DTO моделируют входы; единой
типизированной модели всех ответов, из которой можно без дублирования получить
полный OpenAPI, нет. Проекту нужен официальный машиночитаемый контракт,
Swagger UI в закрытом контуре и автоматическое обнаружение невалидных ссылок и
рассинхронизации ключевых инфраструктурных условий.

Рассматривались три подхода:

- статический YAML: минимальная интеграция и читаемый diff, но обновление при
  изменении API контролируется review и quality gate, а не выводится из кода;
- PHP attributes/annotations со `swagger-php`: удобно при уже аннотированной
  строгой модели ответов, но в текущем проекте перегрузило бы контроллеры либо
  потребовало отдельного слоя OpenAPI-классов и хранимого generated-файла;
- гибрид: общие YAML-схемы плюс генерируемые операции создают два источника
  истины и не окупаются на первом постепенном этапе.

## Решение

Единственный source of truth — `openapi/openapi.yaml` в OpenAPI 3.0.3. Файл
редактируется вручную и не генерируется. Версия 3.0.3 широко поддерживается
выбранными Swagger UI и валидатором и достаточна для фактического контракта.

`@apidevtools/swagger-parser` проверяет структуру и разрешение `$ref`; узкие
репозиторные assertions защищают обязательный вертикальный срез, cookie/CSRF,
идемпотентность, локальную ссылку UI и отсутствие чувствительных имён
конфигурации. `swagger-ui-dist` поставляет pinned assets. Docker image копирует
их вместе со спецификацией, поэтому runtime не зависит от CDN или интернета.

Nginx публикует спецификацию на `/api/openapi.yaml`, а UI на `/api/docs/` в
development и production. Production-доступ осознанно открыт: контракт не
содержит секретов, environment values и development/test identity headers.
Swagger `Try it out` полностью отключён. Реальная авторизация использует
серверную session cookie и CSRF cookie/header; UI не имитирует OAuth/JWT и не
предлагает небезопасный обход этого механизма.

Первый срез фиксирует liveness, bootstrap текущего пользователя/CSRF,
защищённый список заявок и добавление комментария с `Idempotency-Key`. Покрытие
остальных существующих маршрутов добавляется постепенно.

## Последствия

- изменение публичного API должно сопровождаться соответствующим обновлением
  OpenAPI-контракта;
- `docs/api.md` сохраняет бизнесовые, security и эксплуатационные пояснения,
  а формы HTTP-запросов/ответов/статусов постепенно переходят в OpenAPI;
- расхождение спецификации с PHP невозможно полностью исключить генерацией,
  поэтому репрезентативные runtime-тесты и обязательный review остаются частью
  контроля;
- новый runtime-сервис, самописный генератор и внешний CDN не появляются.
