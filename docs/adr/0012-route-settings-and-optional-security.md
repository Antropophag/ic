# Изменение маршрута и необязательный контроль СБ

Статус: заменено в части выбора проверок [ADR 0013](0013-checks-at-request-closure.md);
историческое решение от 25.11.2026. Уточняет ADR 0009.

## Контекст и решение

По договорённости с владельцем и руководителем ИЦ сохраняются два маршрута.
Экспертиза принадлежит «Протоколу», а контроль СБ становится его отдельной
настройкой. Это позволяет завершить заявку после заключения, заранее исключив
ненужную проверку, без отзыва уже поступившей в СБ заявки.

Руководители ИЦ и лаборатории могут изменить маршрут и настройку СБ до первой
публикации экспертного заключения или первого завершения заявки. Пройденная
граница определяется историей: удаление отчёта или заключения её не отменяет.
Оба руководителя имеют одинаковые права; эксперт не изменяет настройку.

При наличии действующего отчёта смена «Акта» на «Протокол» переводит заявку
на экспертизу, обратная смена — в работу с возможностью завершения руководителем.
Приостановленная заявка остаётся на паузе; возобновление следует новому маршруту.
Назначения и документы сохраняются, следующая роль получает уведомление.

Публикация заключения с отключённым СБ завершает заявку и уведомляет инициатора
со ссылками на документы. Решение СБ не создаётся. Удаление заключения возвращает
на экспертизу; повторная публикация использует прежнюю настройку СБ.
Изменение настройки не восстанавливает доступ к старым удалённым документам.

## Совместимость и конкуренция

Миграция добавляет `requests.security_review_required` с default true,
не меняя статусы, документы и решения существующих заявок. В старом запросе
выбора маршрута без `securityReviewRequired` подразумевается true; «Акт» всегда
сохраняет false. Новое значение API принимает только как JSON boolean.

Команды блокируют строку заявки и проверяют lockVersion. Изменение настройки
инвалидирует открытое окно публикации; публикация первой закрывает настройки.
Сохранение настроек без реального изменения отклоняется. Смена, переход,
аудит и постановка уведомлений атомарны и используют штатную идемпотентность.

## Обновление и откат

Перед обновлением сохраняются согласованные резервные копии БД и документов.
Миграция не удаляет данных. Пока новые настройки не использованы, обратная
миграция удаляет только добавленную колонку. После применения настройки или
нового правила смены маршрута rollback отказывается от потери контекста;
восстановление выполняется из копии вместе с предыдущей версией приложения.
