# Маршруты заявки и завершение после решения СБ

Статус: принято, 05.10.2026. Задачи: #358, #359.

## Контекст и решение

Владелец отменил прежнее требование отдельного завершения руководителем после
СБ: оба решения, «Согласовано» и «Не согласовано», завершают полный маршрут.
Отрицательное решение не возвращает заявку в работу. Решение остаётся отдельной
записью с автором и временем, а его сохранение и завершение выполняются одной
транзакцией с аудитом и уведомлением. Назначения и ревизии не меняются.

Руководитель ИЦ и руководитель лаборатории имеют одинаковые права. Они выбирают
«Акт» или «Протокол» до начала работ и меняют маршрут до первой загрузки отчёта.
По «Акту» отчёт оставляет заявку в работе; отдельная команда руководителя
завершает её без экспертизы и СБ. Смена маршрута после удаления отчёта запрещена,
чтобы удаление не позволяло обойти уже выбранный процесс. Повторная загрузка
запускает тот же маршрут. Замена акта инвалидирует незавершённую команду
завершения через lockVersion.

## Последствия

Новые заявки создаются без маршрута. Существующим строкам миграция задаёт
«Протокол», не меняя статусы и не приписывая выбор вымышленному автору.
Проект ещё не запущен: по уточнению владельца исторические решения не переносим,
демо-набор пересоздаётся под новую модель. API принимает только approve/decline;
поддержки прежнего return нет.

Генератор DOCX остаётся генератором черновика отчётного документа для обоих
маршрутов: название шаблона «Акт испытаний» не выбирает маршрут и не заменяет
загрузку утверждённого PDF. Полный маршрут добавляет к отчёту заключение и СБ.

Выбор сохраняется в requests.route, route_selected_by, route_selected_at;
все изменения выбора — в audit_events. Завершение хранится в
request_transitions с автором, временем и ссылкой на версию отчёта для «Акта».
Конкурирующие команды сериализуются блокировкой строки заявки, проверяют
lockVersion и используют существующую HTTP-идемпотентность.

## Миграция и откат

До применения миграции сохраняется резервная копия. Миграция добавляет только
поля и внешний ключ, не завершает существующие заявки и не переписывает решения.
Обратная миграция разрешена, пока новые маршруты и решения не использованы.
После использования откат требует восстановления согласованной копии БД и
хранилища вместе с прежней версией приложения: удалять новый контекст процесса
безвозвратно команда down не позволяет. Демо-данные можно пересоздать штатным
development reset; рабочие данные эта процедура не затрагивает.
