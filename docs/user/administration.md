# Пользователи и роли (администрирование)

Панель содержит вкладки «Пользователи и роли», «Журнал действий» и
«Уведомления». Журналы доступны только активному администратору и работают
исключительно на чтение.

Журнал действий фильтруется по периоду, пользователю, типу, объекту, заявке и
результату. Детали показывают raw тип и только безопасную часть данных: полный
audit payload скрыт, поскольку причины, тексты и технические значения могут
быть чувствительными.

Журнал уведомлений фильтруется по статусу, заявке, событию, получателю,
периоду и проблемности. Тело письма не отображается, а raw `last_error`
всегда заменяется нейтральным сообщением «Ошибка SMTP». `sent` означает принятие письма SMTP transport, но не
гарантирует прочтение. Доставка остаётся at-least-once, поэтому возможен
редкий дубль. Повторно отправить `failed` из панели нельзя.

Версия инструкции: 30.07.2026.

Экран доступен по кнопке «Администрирование» в шапке портала пользователю с
ролью «Администратор портала».

## Завести сотрудника заранее

1. Откройте «Администрирование».
2. Укажите логин AD (`ivanov`) — только латиница, цифры, точка, дефис и
   подчёркивание, без `@` и пробелов.
3. Выберите роль, которую сотрудник должен получить сразу (например,
   «Руководитель ИЦ» или «Эксперт»).
4. Нажмите «Добавить заранее».

Отображаемое имя вводить не нужно: профиль сразу получает базовую роль
«Сотрудник» и выбранную роль, а отображаемое имя, email, подразделение и
должность будут заполнены реальными данными из AD при первом входе сотрудника
через LDAP — до этого момента в списке показывается сам логин.

Если создание профиля прошло успешно, но назначить выбранную роль сразу не
удалось, портал сообщит об этом отдельно — роль можно назначить позже в
списке ниже, без повторного создания профиля.

## Управлять ролями существующего сотрудника

В списке пользователей у каждой роли есть крестик — отзывает роль. Ниже
списка ролей — выпадающий список и кнопка «+» — назначает дополнительную
роль. Оба действия применяются немедленно и не требуют подтверждения.

## Начальные администраторы deployment

При production-развёртывании `make up` добавляет роли «Сотрудник» и
«Администратор портала» логинам из `BOOTSTRAP_ADMIN_AD_LOGINS`. Это add-only
настройка первоначального доступа: удаление логина из `.env` не отзывает уже
выданную роль и не удаляет пользователя. Для отзыва используйте крестик у роли
в этом экране.

Локально отключённый профиль автоматически не включается: bootstrap завершится
с ошибкой и откатит назначения для всего списка. Перед повторным запуском
`make up` профиль нужно активировать штатным административным механизмом.

Bootstrap не проверяет и не создаёт учётную запись в AD. Если локального профиля
ещё нет, он создаётся с логином вместо имени; настоящий профиль заполнится после
первого успешного LDAP-входа. Назначение с `assigned_by = NULL` в данных означает,
что роль выдал deployment bootstrap, а не вошедший в портал администратор.
